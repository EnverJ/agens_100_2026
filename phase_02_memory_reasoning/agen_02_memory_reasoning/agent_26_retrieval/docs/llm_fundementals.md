# LLM Fundamentals — Agent 26: Retrieval

## Key Concepts

- **Cosine similarity in vector space.** Every document and query is represented as a point in a high-dimensional space (typically 384–1536 dimensions, depending on the embedding model). Cosine similarity measures the angle between two vectors: a value of 1.0 means the vectors point in the same direction (identical meaning); 0.0 means orthogonal (unrelated meaning). ChromaDB returns cosine distance (1 − cosine similarity), so the most similar result has the lowest distance. Understanding this inversion — lower score = better match — is essential for correctly reading retrieval output.

- **Query and documents must use the same embedding model.** Embedding models map text into a coordinate space that is specific to their training. If documents were stored with model A and the query is embedded with model B, the resulting vectors live in different spaces and distances are meaningless. This is called an embedding model mismatch and it is one of the most common silent failure modes in retrieval systems. Agent 26 enforces a single embedding model at both ingest and query time.

- **k-NN search complexity.** A brute-force k-nearest-neighbor search computes the distance between the query vector and every document vector in the collection — O(n × d) where n is the number of documents and d is the embedding dimension. For small collections this is fast enough; for large ones, approximate nearest-neighbor (ANN) indexes (HNSW, IVF) reduce this to sub-linear time with a small accuracy trade-off. ChromaDB uses HNSW internally. Knowing this distinction matters when reasoning about retrieval speed at scale.

- **Relevance score interpretation.** Distance scores do not have universal meaning — they are only comparable within the same collection and embedding model. A distance of 0.2 may be excellent in one collection and mediocre in another. Best practice is to calibrate a rejection threshold (e.g., drop any result with distance > 0.5) by examining a sample of queries against known-good answers, rather than assuming a fixed value is always valid. Distance scores are a ranking signal, not an absolute quality indicator.

- **Pre-filtering vs post-filtering.** Metadata pre-filtering (applying the `where` clause before k-NN) reduces the candidate set first and then searches within it — this is more efficient and avoids returning documents that satisfy the vector criterion but fail the metadata criterion. Post-filtering (retrieve top-K then filter) can miss relevant results if the correct documents are outside the top-K before filtering. Agent 26 uses pre-filtering. The trade-off is that a very restrictive `where` clause can reduce the candidate pool so much that k results cannot be filled.
