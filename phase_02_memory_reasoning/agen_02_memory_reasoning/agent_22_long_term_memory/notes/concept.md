# Concept: Long-Term Memory with ChromaDB

Agent 22 exists to solve a problem that Agent 21 deliberately left unsolved: memory that survives beyond the current session. Agent 21's sliding-window store is powerful within a single process lifetime, but the moment the process exits, everything is gone. For agents that need to learn from experience — recalling what happened in previous sessions, retrieving relevant context from past interactions, or building up a knowledge base over time — in-process RAM is not enough. Agent 22 is the first agent in this series to write to disk.

ChromaDB is an embedded vector database designed exactly for this use case. Unlike a relational database where you query by exact column values, ChromaDB stores each piece of text as a high-dimensional vector — a numerical representation of its meaning — and retrieves items by geometric similarity in that vector space. This means you can store "the deployment pipeline failed due to a missing environment variable" and later retrieve it with the query "CI/CD environment config errors," even though none of those exact words appeared in the original text. The database finds semantically related entries, not lexically identical ones.

The key shift from Agent 21 is from positional retrieval to semantic retrieval. Agent 21 returns the last N entries by position. Agent 22 returns the K most relevant entries by meaning. This distinction matters enormously for agents with large memory stores: scanning a list of 10,000 past observations for the one most relevant to the current task is only feasible if you can search by meaning rather than reading them all. The embedding model does the translation from text to vector; ChromaDB does the fast similarity search over the resulting space.

Agent 22 also introduces the metadata layer. Each stored vector is accompanied by a dict of structured metadata — timestamps, session IDs, tags, source labels. This metadata does two things: it makes retrieved results more actionable (the agent knows when and where the memory came from), and it enables pre-filtering before the similarity search runs (retrieve only memories from this week, or only memories tagged "auth"). Understanding how to pair semantic retrieval with metadata filtering is the foundational skill for all RAG-based agents that follow. Agent 23 and Agent 24 are both direct specializations of this pattern applied to SDET workflows.
