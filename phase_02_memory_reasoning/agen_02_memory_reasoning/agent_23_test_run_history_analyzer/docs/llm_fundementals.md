# LLM Fundamentals: Agent 23 — Test Run History Analyzer

- **Serializing structured data to text for embedding**: Embedding models are trained on natural language, not JSON or structured data formats. A raw dict like `{"pass_count": 47, "fail_count": 3}` embeds poorly because the model has no context for what those numbers mean in relation to each other. By converting the struct to a sentence — "47 tests passed, 3 failed, 94% pass rate" — the embedding captures the semantic content of the test outcome rather than the syntactic shape of the JSON. The quality of the serialization directly determines the quality of retrieval.

- **Metadata filtering in ChromaDB**: ChromaDB allows you to attach a metadata dict to each stored document and filter on that metadata before running the similarity search. For test history, this means you can add `suite_name` as a metadata field and then scope queries to a specific suite using `where={"suite_name": "checkout_regression"}`. This pre-filter reduces the candidate set before k-NN runs, improving both precision and speed for suite-specific queries.

- **Relevance of semantic search for test names**: Test suite names are often abbreviated, versioned, or domain-specific ("chk_reg_v2", "login_e2e_smoke"). A keyword search for "checkout regression tests" will miss "chk_reg_v2" entirely. A semantic search on the serialized document — which includes the full context of what the suite does — will find it, because the embedding of the document captures what the suite tests, not just its name.

- **Embedding test failure messages**: Failure messages like "AssertionError: expected 99.99, got 100.00" and "PriceCalculationError: rounding mismatch" are semantically related even though they share no words. By including failure messages in the serialized text document before embedding, the agent makes it possible to retrieve "runs that had pricing calculation errors" even when the exact error message varies across runs and reporters.

- **Natural language QA over structured history**: The key value proposition of Agent 23 is that it turns structured test history into a natural-language-queryable corpus. An SDET can ask "which suites have been slowest this month?" or "when did the auth suite last fail?" without writing any queries. The embedding model acts as the bridge between the human's natural-language intent and the stored structured content — translating both into the same vector space so similarity search can do the matching.
