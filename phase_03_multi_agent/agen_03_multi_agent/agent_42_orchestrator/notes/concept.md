# Concept — Agent 42: Orchestrator

Orchestration exists because multi-step goals cannot be achieved by a single agent call. When a task requires sequential processing — where the output of one stage shapes the input of the next — you need a coordinator that knows the full sequence and manages the handoffs. The orchestrator is that coordinator. It holds the complete picture of what needs to happen and in what order, while the agents it calls remain focused on a single, well-defined job.

The orchestrator pattern differs from the manager-worker pattern introduced in Agent 41 in a fundamental way: manager-worker is about fan-out — one task decomposed into N parallel (or sequential) subtasks, all similar in nature, collected and synthesized at the end. Orchestration is about chaining — a sequence of distinct transformations where each stage produces something qualitatively different from the stage before it. In a pipeline, stage B does not do the same thing as stage A; it does the next thing. The output of stage A is not aggregated with the output of stage B; it becomes the input to stage B.

In the agent context, a "pipeline" means a series of agent calls where each call transforms data in a specific way and the result of each transformation is passed forward. A text summarizer followed by a sentiment classifier followed by a categorization agent is a pipeline. Each agent in the chain has a clear contract: here is what I receive, here is what I return. The orchestrator enforces that contract at every handoff, translating the output format of one agent into the input format of the next if necessary. The pipeline agents themselves have no knowledge of this — they see only their own input and produce only their own output.

This connects directly to Agent 41: where Agent 41 introduced the concept of a coordinator that decomposes and aggregates, Agent 42 introduces the concept of a coordinator that chains. Both are forms of orchestration, but they represent different structural patterns. Agent 41 is a star topology (manager at the center, workers at the edges). Agent 42 is a linear topology (stages connected in sequence). Understanding both is necessary before moving to more complex patterns such as conditional routing, parallel pipelines, and hierarchical orchestration.
