## Core Concept – Agent 18

Every agent before Agent 18 used the LLM for general reasoning: answer questions, summarize context, classify input. Agent 18 is the first agent that uses the LLM for a specific professional discipline — software testing. The shift is not in the model or the API; it is in the system prompt. By framing the LLM as a senior SDET and providing explicit output requirements, the same model that generates blog posts now generates test cases that cover happy paths, edge cases, and negative scenarios.

The requirement-to-test-case transformation is one of the highest-leverage applications of LLMs in QA. A junior tester given a feature specification might spend two to four hours writing test cases. An experienced SDET might do it in thirty minutes but with significantly more coverage depth. Agent 18 collapses that time to seconds, with coverage determined by the quality of the prompt. This does not replace testers — it removes the mechanical parts of the job so testers can focus on the parts that require judgment.

The output format is a JSON list of test case objects. Each object has a fixed schema: id, title, steps (a list of strings), expected_result (a string), and type (one of: "happy_path", "edge_case", "negative"). The fixed schema matters because the output of Agent 18 is the input to downstream agents — Agent 19 will validate results against expected_result fields, and future agents will execute test steps. If the schema drifts, the pipeline breaks. Enforcing structure at this stage, through both prompt instructions and output parsing, is what makes the test cases machine-readable rather than just human-readable.

The builder should run Agent 18 on a real requirement from their own product — a Zomato restaurant listing page, a payment flow, a search filter. The test cases it generates will reveal both the power of the approach (surprising coverage breadth) and its limits (hallucinated steps for domain-specific workflows). Those limits are the motivation for Agent 19 and the human-in-the-loop review patterns introduced later.
